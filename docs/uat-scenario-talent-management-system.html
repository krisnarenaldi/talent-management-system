📋 UAT Scenario — Talent Management System

Tanggal UAT: 16 September 2026 Versi: 1.0 Prepared by: Tim Pengembang TMS
1. User & Role

Sistem TMS memiliki 4 role pengguna dengan hak akses berbeda. Setiap role mewakili fungsi bisnis yang spesifik.

Role Label Akses & Tanggung Jawab Tidak Bisa
admin Administrator Full akses ke seluruh modul. Kelola user, master data (client, posisi, agreement type, blacklist status type), approve/revoke blacklist, lihat analytics. —
hr HR / Recruiter Input kandidat, buat lamaran, update stage pipeline, input ke blacklist, lihat analytics. Hanya bisa edit lamaran yang ditugaskan kepadanya sendiri. Kelola user, approve/revoke blacklist, akses payroll.
manager Manager / HRD Semua akses HR + approve/revoke blacklist. Lihat data payroll karyawan. Lihat semua lamaran. Kelola user & master data global.
pm Project Manager Lihat daftar karyawan (placement) & blacklist. Tidak bisa membuat atau edit data apapun. Semua operasi tulis. Analytics pipeline.

3. Skenario UAT

Jalankan skenario secara berurutan. Setiap skenario mencantumkan: aktor, langkah, dan hasil yang diharapkan.

Modul D — Lamaran & Pipeline Rekrutmen
Pipeline Rekrutmen (berurutan):
Dijadwalkan_Interview→ Konfirmasi_Kehadiran→ Interview_HR→ Psikotest→ Interview_User→ Offering→ Tanda_Tangan_Kontrak→ Onboarding→ Existing (Hired)
Rejectedatau Withdrawn(bisa dari tahap mana saja)
D1
Buat Lamaran Baru
hr
  1. Login HR → buka menu Lamaran → klik Buat Lamaran.
  2. Pilih kandidat: Andi Firmansyah.
  3. Pilih posisi: Backend Developer – PT Maju Bersama.
  4. Pilih recruiter: Sari HR.
  5. Stage awal: Dijadwalkan_Interview (default).
  6. Klik Simpan.

✅ Hasil diharapkan: Lamaran dibuat dengan status active, stage Dijadwalkan_Interview. Muncul di daftar Lamaran.

D2
Update Pipeline Stage — Maju Bertahap
hr
  1. Buka lamaran Andi Firmansyah → klik Update Stage.
  2. Pilih stage: Konfirmasi_Kehadiran → isi tanggal jadwal, result ok, catatan → Simpan.
  3. Update lagi ke Interview_HR → result pass, tanggal, catatan → Simpan.
  4. Update ke Interview_User (lewati Psikotest untuk variasi) → result lolos → Simpan.
  5. Update ke Offering → isi Gaji Ditawarkan → Simpan.
  6. Update ke Tanda_Tangan_Kontrak → Simpan.
  7. Update ke Onboarding → Simpan.
  8. Update ke Existing → Simpan.

✅ Hasil diharapkan: Stage bergerak maju sesuai pipeline. Saat masuk Existing: status lamaran menjadi hired dan karyawan baru otomatis terbentuk di modul Karyawan.

D3
Reject Kandidat di Tengah Pipeline
hr
  1. Buat lamaran baru untuk kandidat Budi Santoso (dari seed data) → posisi yang sama.
  2. Update stage ke Interview_HR → result fail → Simpan.
  3. Coba update ke Interview_User — sistem harus menolak.
  4. Update ke Rejected dengan alasan "Tidak memenuhi kualifikasi teknis" → Simpan.

✅ Hasil diharapkan: Setelah result fail, transisi maju ditolak. Lamaran berhasil ditutup dengan status rejected. Tidak bisa di-update lagi.

D4
Cegah Duplikat Lamaran Aktif
hr
  1. Coba buat lamaran kedua untuk kandidat yang sama (Andi Firmansyah) ke posisi Backend Developer yang sama.

✅ Hasil diharapkan: Sistem menolak dengan pesan "Kandidat sudah memiliki lamaran aktif untuk posisi ini".

Modul E — Blacklist
E1
Tambah Kandidat ke Blacklist (HR)
hr
  1. Login HR → buka menu Blacklist → klik Tambah Blacklist.
  2. Target: pilih Kandidat → cari Siti Aminah.
  3. Status Type: "Tidak Hadir Interview Tanpa Konfirmasi (No-Show)".
  4. Isi Alasan: "Tidak hadir 2x interview tanpa kabar".
  5. Isi Catatan, tanggal blacklist: hari ini, PIC: otomatis terisi HR.
  6. Klik Simpan.

✅ Hasil diharapkan: Record blacklist tersimpan dengan status Menunggu Approval (is_approved = false). Muncul di daftar blacklist.

E2
Approve Blacklist (Manager/Admin)
manager
  1. Login sebagai Manager → buka menu Blacklist.
  2. Filter approval status: Pending → temukan record Siti Aminah.
  3. Klik Approve pada record tersebut → konfirmasi.

✅ Hasil diharapkan: Status menjadi Approved. Nama approver tercatat (Manager). Kandidat kini tidak bisa dibuatkan lamaran baru.

E3
Blokir Lamaran untuk Kandidat Blacklisted
hr
  1. Login HR → coba buat lamaran baru untuk Siti Aminah.

✅ Hasil diharapkan: Sistem menolak dengan pesan "Kandidat ini sedang dalam daftar blacklist dan tidak dapat diproses" beserta alasannya.

E4
Cabut (Revoke) Blacklist
manager
  1. Login Manager → buka Blacklist → temukan record Siti Aminah.
  2. Klik Cabut Blacklist → konfirmasi.
  3. Setelah dicabut, coba buat lamaran baru untuk Siti Aminah.

✅ Hasil diharapkan: Blacklist tidak lagi aktif (is_active = false). Tidak muncul di daftar aktif. Lamaran baru untuk Siti Aminah bisa dibuat.

E5
Blacklist Karyawan Aktif
hr
  1. Buka menu Blacklist → Tambah Blacklist.
  2. Ubah target ke Karyawan → cari Andi Firmansyah (yang baru di-hire).
  3. Status Type: "Bermasalah di Tempat Kerja Client".
  4. Isi alasan & catatan → Simpan.

✅ Hasil diharapkan: Record blacklist karyawan tersimpan, menunggu approval manager.

Modul F — Karyawan
F1
Verifikasi Karyawan Otomatis dari Hiring
hr
  1. Setelah skenario D2 selesai (Andi Firmansyah masuk Existing), buka menu Karyawan.
  2. Cari Andi Firmansyah.
  3. Verifikasi data: nama, data kandidat (NIK, TTL, dll) sudah ter-import otomatis.
  4. Lengkapi data karyawan: NIP, Placement "Site Jakarta", Role Level "Junior Engineer", email kantor.

✅ Hasil diharapkan: Karyawan terbentuk otomatis saat lamaran masuk stage Existing. Data dasar sudah terisi dari profil kandidat.

F2
Tambah Kontrak Karyawan
manager
  1. Buka detail karyawan Andi Firmansyah → tab Kontrak.
  2. Klik Tambah Kontrak → isi: Tipe Perjanjian PKWT, No. Kontrak, Durasi 12 bulan, Tanggal Mulai: hari ini.
  3. Simpan.

✅ Hasil diharapkan: Kontrak tersimpan. End date dihitung otomatis (join_date + 12 bulan). Status kontrak: aktif.

F3
Akses Payroll (Manager Only)
manager
  1. Login Manager → buka detail karyawan → tab Payroll.
  2. Isi data: THP, Bank, No. Rekening, BPJS TK, BPJS Kesehatan, NPWP → Simpan.
  3. Logout, login sebagai HR → coba buka tab Payroll karyawan yang sama.

✅ Hasil diharapkan: Manager bisa melihat & isi payroll. HR tidak dapat mengakses data payroll (redirect atau pesan tidak punya akses).

Dashboard Summary
manager

  2. Verifikasi card summary: Total Kandidat Aktif, Total Karyawan Aktif, Kontrak Berakhir dalam 30 Hari.
  3. Verifikasi tabel Lamaran Terbaru dan Kontrak Segera Berakhir.

✅ Hasil diharapkan: Semua angka terisi dan sesuai data yang telah diinput selama UAT.

G2
Analytics Pipeline & Success Rate
manager
  1. Buka halaman Analytics.
  2. Periksa grafik Pipeline Breakdown — harus menampilkan distribusi kandidat per stage.
  3. Periksa Success Rate by Position dan by Source Channel.

✅ Hasil diharapkan: Grafik tampil dengan data yang mencerminkan skenario D1–D3. Filter berfungsi.

Modul H — Verifikasi Pembatasan Role
H1
PM — Read-only Access
pm
  1. Login sebagai PM (pm@altek.id).
  2. Buka menu Karyawan → verifikasi bisa melihat daftar karyawan.
  3. Buka menu Blacklist → verifikasi bisa melihat daftar blacklist.
  4. Coba klik tombol Tambah / Edit / Hapus — pastikan tidak muncul atau tidak bisa diklik.
  5. Coba akses Admin → Users — pastikan redirect atau pesan tidak punya akses.

✅ Hasil diharapkan: PM hanya bisa membaca. Semua aksi tulis dibatasi.

H2
HR — Tidak Bisa Edit Lamaran HR Lain
hr
  1. Buat user HR kedua: hr2@altek.id (via Admin).
  2. Buat lamaran baru dengan recruiter = hr2@altek.id.
  3. Login sebagai hr.sari@altek.id → coba update stage lamaran milik hr2.

✅ Hasil diharapkan: Sistem menolak dengan pesan "Anda tidak memiliki akses untuk mengedit lamaran yang ditugaskan ke recruiter lain".
